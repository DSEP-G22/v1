## Why the telecom supplement is required

Bitext's 11 categories (`ORDER, SHIPPING, DELIVERY, REFUND, INVOICE, PAYMENT, CONTACT, FEEDBACK,
ACCOUNT, SUBSCRIPTION, CANCEL`) are all generic e-commerce/account support, **none** of them
describe a telecom fault (no internet, router LED state, line sync, no dial tone, field service).
A classifier trained on Bitext alone has a `network_operations`/`field_service` recall of exactly
**0%** by construction, those classes never appear in training data.

`scripts/generate_telecom_supplement.py` generates 410 rows (250 `network_operations`, 160
`field_service`) from 41 hand-written phrasing templates x lexical-variation slot-filling (router
noun, timeframe, LED colour), covering: no-internet, router LED issues, slow speed, intermittent
connection, no dial tone, line-sync issues, area outages (`network_operations`); technician
scheduling, missed appointments, installation requests, on-site cabling issues, visit-status
checks (`field_service`). Seeded (`random.seed(22)`) for reproducibility, regenerate with
`python scripts/generate_telecom_supplement.py`.

**Caveat, stated plainly:** these are templated, not literally hand-typed one at a time, see
`08-evaluation.md` for how this affects the classifier's (very high) macro-F1 and what a
production dataset would need instead (real historical tickets).

## Bitext category -> Department mapping

`config/department_map.yaml`:

```yaml
category_to_department:
  ORDER: general
  SHIPPING: general
  DELIVERY: general
  REFUND: billing
  INVOICE: billing
  PAYMENT: billing
  CONTACT: general
  FEEDBACK: general
  ACCOUNT: technical_support
  SUBSCRIPTION: technical_support
  CANCEL: retention
  NETWORK: network_operations       # telecom supplement only
  FIELDSERVICE: field_service       # telecom supplement only
```

This is data, not code, `notebooks/01_data_preparation.ipynb` loads it via `yaml.safe_load`, so
re-mapping a category doesn't require touching the notebook.

## Cleaning

The `instruction` column contains templated slots like `{{Order Number}}`. These are **stripped**
(not randomised, the surrounding phrasing already carries the classification signal), then
whitespace is collapsed. Left in, a classifier learns to key off the literal `{{`/`}}` characters
instead of the language around them.

## Split methodology

Stratified 80/10/10 (train/val/test) by `department`, `random_state=22`, via
`sklearn.model_selection.train_test_split` (two-step: 80/20 then 50/50 of the 20%). Stratifying
on `department` (not `category` or `intent`) matches what notebook 02 actually trains against.
