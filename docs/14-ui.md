# 14. Agent Workspace (UI)

Implements SRS §3.1 UI-1 to UI-7 with the stack named in `docs/Appendix_C-technology-stack.md`:
React 18 + TypeScript 5, Vite 5, Tailwind CSS 3, TanStack Query 5, native WebSocket with polling
fallback, Recharts 2, WaveSurfer.js 7. Source lives in `v1/frontend/`.

UI-8 (wireframes, detailed visual design) remains deferred as the SRS states; this document
records what was built, not a visual specification.

---

## 1. Running it

The frontend is a **standalone deployable**. FastAPI serves the API only; it does not serve the
bundle and there is no `/ui` route.

### Development, two processes

Terminal 1, the API:

```powershell
cd d:\DSEP22\v1
.venv\Scripts\python.exe -m runtime.local     # http://localhost:8000
```

Terminal 2, the UI:

```powershell
cd d:\DSEP22\v1\frontend
npm install
npm run dev                                   # http://127.0.0.1:5300
```

Open **http://127.0.0.1:5300** and sign in with `dev-agent-token`, `dev-lead-token` or
`dev-admin-token`.

Vite proxies `/workspace`, `/admin` and `/api`, including the WebSocket, to :8000, so during
development the browser sees a single origin and CORS never comes into play.

> **Port 5300, not Vite's 5173.** Windows reserves 5104-5203 for Hyper-V/WSL on this machine, so
> binding 5173 fails with `EACCES: permission denied` even with nothing listening. Confirm your own
> reserved ranges with `netsh interface ipv4 show excludedportrange protocol=tcp`, and change
> `server.port` in `vite.config.ts` if 5300 is taken too.

### Deployed, separate origins

```bash
cd frontend
VITE_API_BASE=https://api.example.com npm run build   # emits dist/
```

Serve `dist/` from any static host (nginx, Caddy, Vercel, S3+CloudFront). The host must route all
unknown paths to `index.html`, otherwise a refresh on `/tickets/<id>` 404s.

Then add that frontend origin to the API's allow-list:

```
CORS_ALLOW_ORIGINS=["https://workspace.example.com"]
```

`cors_allow_origins` is an explicit list and never `*`: the API accepts credentials in the
`Authorization` header, and a wildcard origin with credentials is precisely the configuration that
lets any site read an authenticated response.

### Both URLs at a glance

| Thing | Development | Deployed |
|---|---|---|
| UI | http://127.0.0.1:5300 | your static host |
| API | http://localhost:8000 | `VITE_API_BASE` |
| API docs | http://localhost:8000/docs, `/workspace/docs`, `/admin/docs` | same paths |

## 2. Screens

| Req | Screen | Route | Notes |
|---|---|---|---|
| UI-1 | Login | `/login` | v1 has no password store; the credential is the static role token from `libs/platform/auth.py`. The failure message is identical for an unknown user and a bad token, so it discloses nothing. SSO is out of scope. |

| UI-3 | Ticket workspace | `/tickets/:id` | Three regions side by side (`xl:grid-cols-3`), stacking below that width. |

| UI-5 | Administration | `/admin` | Tabs: users, routing rules, thresholds, models, action registry, dead-letter queue with replay. Admin only. |
| UI-6 | Onboarding | `/onboarding` | SOP upload with per-document ingestion status and the knowledge-base search preview. Admin only. |
| UI-7 | Common standards | all | See §4. |

### UI-3 in detail

**Evidence**, original customer text; an audio player (WaveSurfer) with the transcript rendered
beside it, each segment shaded by confidence and clickable to seek; image thumbnails with the VLM
summary and its extracted fields; the fused text broken into fragments, each labelled with the
modality, source attachment, model version and confidence that produced it.

**Diagnosis**, department with confidence, priority band and score with the weighted contributing
signals drawn as bars, sentiment, intent, fault with confidence, the rationale, and every retrieved
citation expandable to its source excerpt. Unverified citations are marked as such rather than
hidden, and a diagnosis below the confidence threshold shows the "not asserting this fault" notice.

**Act**, the editable draft with the immutable AI original available for comparison, policy
findings, the recommended action with its parameters, and `Approve & Send`, `Save Draft`,
`Execute Action`, `Reject Suggestion`, `Reassign`, `Escalate`. Rejection requires a reason code,
enforced inline at the field. `Execute Action` is disabled with an explanatory tooltip for the agent
role; the server enforces the same rule and returns 403.

## 3. Backend additions this required

The UI needed data the API did not expose. Added in this change:

| Area | Change |
|---|---|
| `queue_projection` | Nine denormalised columns, `channel`, `priority_score`, `department_confidence`, `fault`, `diagnosis_confidence`, `modalities`, `flags`, `ticket_created_at`, `sla_due_at`, plus an ordering index. The queue view still reads one table and joins nothing (ADR-009). |
| `projector_svc` | Now projects the full row from ticket, triage, diagnosis, payload and attachments, and `sync_state` re-projects after every workspace command. |
| `GET /workspace/me` | Token → identity, for the login screen. |
| `GET /workspace/tickets/{id}` | Now returns customer, attachments with their transcripts and visual summaries, provenance, triage signals and alternatives, citations **with source excerpts**, recommendations, and the decision history. |
| `GET …/attachments/{id}/content` | Streams stored media, scoped by ticket so an attachment ID alone cannot read another ticket's evidence. |
| `POST …/reassign`, `POST …/escalate` | Back the two UI-3 buttons that had no endpoint; both write an `agent_decision`. |
| `GET /workspace/dashboard` | UI-4 metrics. Lead/admin only. |
| `GET /admin/users`, `/admin/models` | UI-5 user list and declared-vs-active model versions. |
| `GET/POST /admin/knowledge/documents`, `GET /admin/knowledge/search` | UI-6 upload, status list and search preview. |
| `WS /workspace/ws/queue` | Now authenticates (token as a query parameter, a browser cannot set a header on a WebSocket), pushes only on change, and closes with 1008 on a bad token. |
| CORS | `CORSMiddleware` with an explicit origin allow-list (`cors_allow_origins`), credentials enabled, and the `Authorization`, `Content-Type`, `X-Correlation-Id` and `Idempotency-Key` headers permitted. Required because the frontend now runs on its own origin. |

`libs/platform/auth.py` grew `resolve_user_for_token` so the HTTP dependency and the WebSocket
handshake validate identically.

**Architecture note.** `admin_api` calling `knowledge_ingest` made `tests/architecture/test_imports.py`
fail. `knowledge_ingest` consumes no topic and owns its tables exclusively, the same "library, not
a consumer" shape already granted to `retrieval_svc`, so it was added to `_LIBRARY_SERVICES` with
the reasoning recorded in the test. The single-writer test still governs table access.

## 4. UI-7 compliance

- **Navigation and breadcrumb** on every authenticated screen; navigation entries are filtered by role.
- **AI banner**, "AI-generated, review before sending" is rendered in the Act region as a
  persistent, non-dismissible note.
- **Keyboard shortcuts**, queue: `j`/`k` move, `Enter` opens, `r` refreshes; ticket: `Escape`
  returns to the queue. All are suppressed while focus is in a form field. Rows are focusable and
  respond to `Enter`/`Space`, so the queue is fully operable without a mouse.
- **Toasts** for success, inline field-level messages for validation (reason code, upload fields).
- **One error component** (`ErrorPanel`) used everywhere, showing a human-readable message, the
  correlation ID that was sent as `X-Correlation-Id`, the status, and a retry button.
- **Focus**, a global `:focus-visible` outline plus a skip-to-content link.
- **Colour**, priority carries a glyph (`▲▲ ▲ ■ ▼`) and a written label as well as colour;
  confidence shows a numeric percentage beside its bar; transcript confidence shading is
  supplementary to a per-segment tooltip. Band colours are the AA-contrast tokens in
  `tailwind.config.js`.

## 5. Verified end to end

With `APP_PROFILE=stub`, seeded, one text+audio+image ticket posted:

- queue row returned with band, score, all three modality flags, department, fault and SLA;
- ticket detail returned 2 attachments (audio with transcript, image with visual summary),
  3 provenance fragments, 6 triage signals, a draft;
- audio streamed as `audio/wav` (64 044 bytes), image as `image/png`; a mismatched ticket ID
  returned 404;
- unauthenticated queue → 401; agent on `/dashboard` → 403; lead → 200;
- lock → reassign → escalate → draft edit (revision 3) → approve → `SENT` delivery with a non-null
  `approval_id`; `agent_decision` rows `REASSIGN, ESCALATE, APPROVE_SEND`;
- dashboard then reported `acceptance_rate 1.0`, `edit_rate 1.0`;
- all six admin/onboarding endpoints 200, knowledge search returned ranked hits;
- `APP_PROFILE=stub pytest` → 42 passed.

After the split into two deployables, re-verified: `/ui` now 404s on the API; a CORS preflight from
`http://localhost:5300` returns the allow-origin, allow-credentials and allow-headers response;
a request carrying `Origin: http://evil.example` gets **no** allow-origin header; the Vite dev
server serves `/`, `/queue` and `/tickets/<id>` (SPA fallback, no `/ui` basename); and the API
reached through the dev proxy returned the queue and `/admin/models`.

## 6. Known limitations

1. **Routing rules and thresholds are read-only.** The admin API writes routing rules to YAML read
   at start-up, and thresholds come from `.env`; hot-reload into running consumers is not
   implemented. The screens say so rather than offering an editor that silently needs a restart.
2. **Historical ticket import (part of UI-6) is not built.** That path exists only as the
   evaluation dataset loader, so no control is offered for it.
3. **Auth is the static-token stand-in**, not an IdP; roles and their enforcement are real, the
   credential store is not. The token is held in `localStorage`, which is acceptable for a local
   demonstration and not for production, with the frontend on its own origin, a production build
   should move to short-lived cookies or an IdP rather than keeping a bearer token in web storage.
4. **The WebSocket polls the projection** every 2 s server-side and pushes on change; the in-process
   broker has no change feed. Well inside the 5 s of REQ-WKS-2, but it is polling, not a push.
5. **One JS bundle, ~724 kB** (212 kB gzipped), Recharts and WaveSurfer dominate. Route-level code
   splitting is the obvious fix if it matters.
6. **No frontend test suite.** The UI was verified by driving its endpoints (§5), not by component
   tests; Vitest + Testing Library is the natural addition.
