# 11 — Troubleshooting

Consolidated symptom -> cause -> fix, ranked roughly by likelihood. Items marked **(verified)**
were actually hit and fixed during this build, not projected from the implementation plan.

| # | Symptom | Likely cause | Fix / debug |
|---|---|---|---|
| 1 | **(verified)** A ticket intermittently reaches `AGGREGATED`/`READY_FOR_AGENT` with a fragment (e.g. `[CUSTOMER_TEXT]`) missing even though every attachment succeeded | Race in `aggregator_svc`: the transaction that detects "all items received" reused a session/snapshot from *before* a sibling done-handler's commit (SQLite snapshot isolation across concurrent broker threads) | Fixed in `services/aggregator_svc/handler.py::_handle_done` — finalize always runs in a **brand-new** `session_scope`, never the session that just marked completion. See the function's docstring for the full mechanism. |
| 2 | **(verified)** Two broker worker threads racing on `aggregation_state.received_set` lose each other's writes (ticket never completes) | Read-modify-write on a JSON list column from concurrent threads/transactions — classic lost update | Fixed by replacing `received_set` with an append-only `aggregation_received_item` table, unique on `(ticket_id, item)`, inserted via `ON CONFLICT DO NOTHING` — see `libs/platform/db/models.py::AggregationReceivedItemRow` docstring |
| 3 | **(verified)** `StubGenerator` returns the wrong canned response (e.g. a diagnosis-shaped JSON when a draft was requested) | `StubGenerator._guess_kind()` keyword-sniffs the prompt text; the draft prompt template mentions "fault" (from the diagnosis summary line), which matches the diagnosis-kind heuristic before the draft-kind one | Always pass `prompt_kind=` explicitly when calling `generate`/`generate_json` from a service — don't rely on the guess. See `services/response_svc/handler.py` and `services/orchestrator_svc/handler.py`. |
| 4 | **(verified)** A notebook that calls `libs.platform.registry.build_ports` behaves like a live Ollama server is required, times out, or gives nonsensical latency numbers | `APP_PROFILE` was never set in the notebook kernel's process env — `get_settings()` silently defaults to profile `cpu` (real adapters), not `stub` | The shared `_SETUP_CELL` in `notebooks/_build_notebooks.py` now does `os.environ.setdefault("APP_PROFILE", "stub")` — every regenerated notebook has this. If you see this again, check the cell ran before any `libs.platform.config`/`registry` import. |
| 5 | Ticket never leaves `PROCESSING` | Aggregation completion set never satisfied — a failed attachment produced no `done` event | Inspect `aggregation_received_item` for the ticket; confirm `audio_svc`/`image_svc`'s `except` branch still publishes `tickets.audio.done`/`tickets.image.done` with `status=failed` (it does — see their handlers' final `with session_scope` block, which runs unconditionally); confirm the sweeper thread is alive (`runtime/wiring.py::App._sweep_loop`, 5s interval) |
| 6 | LLM returns prose, `json.JSONDecodeError` | Small quantised model ignoring `format: json` | `libs/platform/models/llm.py::_extract_json()` already finds the outermost `{...}` before parsing, and `generate_json` does one repair call via `models/prompts/llm/repair.txt` before giving up (`GenerationInvalid`); lower `temperature`, shorten the prompt, or `ollama show <model>` to confirm instruction support |
| 7 | `httpx.ReadTimeout` on the first LLM/VLM call | Cold model load in Ollama | Raise `llm_timeout_s` for the first call; `ollama ps` to confirm the model is resident; consider a one-token pre-warm request at startup |
| 8 | `connection refused` to `:11434` | `ollama serve` not running, or bound to another host | `curl http://localhost:11434/api/tags`; on Windows check the tray service; set `OLLAMA_HOST=0.0.0.0` if calling from a container |
| 9 | Duplicate rows after a broker retry | Non-idempotent writer | Every writer that can be redelivered must have a matching unique constraint and use `ON CONFLICT DO NOTHING` (see `libs/platform/db/repositories.py` — `AudioTranscriptRepo.upsert`, `UnifiedPayloadRepo.create`, `ActionExecutionRepo.create_if_absent`, `AggregationReceivedItemRepo.mark`) — the constraint is the arbiter, not the application code |
| 10 | `sqlite3.OperationalError: database is locked` | Concurrent writes from broker threads, or a session held open across threads | WAL mode + short transactions are already the default (`libs/platform/db/session.py`); confirm no code path passes a `Session` between threads — one `session_scope` per handler invocation, always |
| 11 | Classifier predicts only 3-4 departments | The Bitext-only classifier has zero telecom coverage | The telecom supplement (`data/telecom_supplement.csv`, `scripts/generate_telecom_supplement.py`) is mandatory, not optional — see `03-data-preparation.md`; confirm `class_weight="balanced"` in notebook 02 |
| 12 | Citations always unverified / `citation_verification_rate` is NaN | Under `APP_PROFILE=stub`, `StubGenerator`'s canned citation `chunk_id="c1"` never matches a real retrieved chunk id | Expected under the stub profile — see `08-evaluation.md`. Under a real profile: print the retrieved context's chunk ids next to the LLM output; short opaque ids (already the design — `<doc_id>:<index>`) should map cleanly if the prompt actually shows them to the model |
| 13 | Retrieval quality collapses after changing the embedding model | Vector index built with a different model | `libs/platform/vector/inmemory.py::InMemoryVectorIndex` already refuses to query/upsert on a model mismatch (`EmbeddingModelMismatch`) — delete `v1_data/vectors.json` and re-run `scripts/seed.py` to rebuild with the new model |
| 14 | VLM invents LEDs not in the image | Over-permissive prompt | `models/prompts/vlm/*.txt` already constrain to "report only what is visible; use unknown"; lower temperature further; cross-check against `HeuristicLedExtractor`'s output and flag disagreement |
| 15 | WER far worse than published Whisper numbers | Wrong sample rate, wrong language hint, or (as in this repo's sample audio) no ground truth at all | Resample to 16kHz mono; pass `language="en"`; see `06-vlm-and-asr.md` — this repo's two sample audio files have no labelled reference transcript, so WER isn't computable here regardless |
| 16 | `import services.x` fails in tests | Missing `__init__.py`, or the package not reinstalled after adding a directory | `uv pip install -e ".[dev]" --python .venv` again; run `pytest` from `v1/` |
| 17 | Pipeline works in the demo but hangs in a test | Broker worker threads not joined/not daemonised | `InProcessBroker` threads are `daemon=True` and `stop()` joins them with a 5s timeout; call `broker.stop()` in a `finally`/fixture teardown, always |
| 18 | QLoRA OOM (notebook 03, if run) | 8B base on <12GB VRAM | Switch `BASE_MODEL_ID` to a 3B model, enable `gradient_checkpointing=True`, reduce `max_seq_len` |
| 19 | `ollama create` fails on the GGUF (notebook 03, if run) | Converted the bare adapter instead of the merged model, or an unsupported base architecture | `merge_and_unload()` first, then convert; confirm `llama.cpp` supports the base architecture |
| 20 | A new repository write method silently violates the single-writer rule | `tests/architecture/test_single_writer.py` only tracks methods listed in `libs/platform/db/ownership.py::WRITE_METHOD_OWNERS` | Add the new method + its owning package(s) to `WRITE_METHOD_OWNERS` when adding a mutating repository method — an unlisted method is invisible to the test, not automatically flagged |
